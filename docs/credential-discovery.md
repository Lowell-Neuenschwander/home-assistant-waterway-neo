# Credential discovery

Waterway's app does not currently display the PubNub publish key, subscribe key,
or controller channel required by this integration. Version 0.1 therefore
targets advanced users who can inspect traffic generated by their own device and
app.

## Values required

You need these three exact values:

- PubNub publish key
- PubNub subscribe key
- Controller-specific channel

The controller's LAN address is separate and should be reserved in DHCP.

## Safe discovery process

1. Confirm the official Waterway app can read the spa while the phone is on the
   same trusted Wi-Fi network.
2. Capture only your own phone/controller traffic using a debugging proxy,
   firewall flow log, or packet-capture environment that you administer.
3. In the app, open the controller and change the target by one degree, then put
   it back. This creates a short, identifiable command exchange.
4. Locate requests to a `pubnub.com` host. The publish and subscribe URL paths
   contain the application keys and controller channel.
5. Store the values directly in Home Assistant's setup form. Do not paste them
   into a GitHub issue, chat, forum, or public configuration file.
6. Stop and delete the capture after setup if it is no longer needed.

TLS interception may require installing a temporary certificate on the phone.
Only do this on a device and network you own, remove the certificate afterward,
and never weaken certificate validation on the spa controller or Home Assistant.

## What to redact when requesting help

Redact the complete publish key, subscribe key, channel, MAC address, public IP,
and any authorization headers. The built-in Home Assistant diagnostics output
already redacts the three configured cloud values.

Automatic onboarding without traffic inspection is a planned enhancement. If a
future Waterway API provides an official credential flow, this manual process
will be removed.
